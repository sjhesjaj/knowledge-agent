## 2. 工作包 A1：完整数词（R4）

### 复现（修复前）

在验收方冻结的上一候选副本上跑本轮复现脚本，两例都错误交付：

```text
一万两千件  -> 提取 ('2000','件')   来源 2000 件时"正常"通过校验并保存
二点五天    -> 提取 ('5','天')      来源 5 天时"正常"通过校验并保存
```

### 根因

上一轮只把 `百`、`千` 加进字符类，字符类本身仍然**停在支持范围的边界**。正则从左
向右扫描，`一万两千件` 里 `一万` 不在类内，于是匹配从 `两千` 开始——一个模型编造的
数字，正好穿上了证据自己的数值。截断出来的数比识别不出来危险得多：它看起来完全合法。

### 修复

数词体扩大到**包含本模块并不转换的写法**（`万`、`亿`、`兆`、`点`），数字、小数点与
中文数词共用一个字符类，因此数词总是被整个捕获；转换与否是**捕获之后**的判断：

```python
_NUMERAL_BODY = r"[\d.零〇一二两三四五六七八九十百千万亿兆点]+"

def parse_numeral(token) -> str | None:   # None = 完整数词，但本模块不转换
```

不可转换的数词以 `?原文` 作为比对身份，只可能等于证据里**一模一样**的数词，永远
不会等于任何被算出来的数字。判定链因此是"整词提取 → 能否转换 → 与证据比对"，
中间没有任何一步可以退而求其次。

明确不支持并因此返回 `None`：`万`/`亿`/`兆` 量级、`点` 小数、`二〇二五`/`五六`
这类无位值字的连写、以及 `十百` 这种位值不递减的乱序串。

### 修复后（A1 矩阵，全部经 `validate_answer` 端到端）

| 证据 | 答案数词 | 提取 | 预期 | 结果 |
|---|---|---|---|---|
| 234 件 | 二百三十四件 | `('234','件')` | 可交付 | ✔ |
| 34 件 | 二百三十四件 | `('234','件')` | 拦截 | ✔ |
| 2000 件 | 两千件 | `('2000','件')` | 可交付 | ✔ |
| 2000 件 | 一万两千件 | `('?一万两千','件')` | 拦截 | ✔ |
| 5 天 | 二点五天 | `('?二点五','天')` | 拦截 | ✔ |

`105`、`42`、`15`、`350`、`2.5` 等已支持写法仍然正确转换（`CompleteNumeralTests`）。

## 3. 工作包 A2：数值的修饰关系（R5）

### 复现（修复前）

来源 5 天、问句猜测 99 天。六句全部被放行并保存，其中两句语义相反：

```text
不是99天而是5天                        放行（正确）
不是5天而是99天                        放行（错误 —— 用词相同，只有位置不同）
每年99天且可以先休5天                   放行（错误）
每年99天且没有特殊限制                  放行（错误）
并不是所有人都有99天但正式员工每年确实有99天  放行（错误）
如果入职满一年则每年有99天               放行（错误）
```

### 根因

上一轮把判定范围从整段缩小到"标点分句"，但**段内的逻辑没变**：先对分句做
`set`，再问"这一段里有没有任意一个有依据的同量词数字，或任意一个否定/假设词"。
缩小字符串范围代替不了"这个修饰到底在修饰哪个数"。集合去重之后，同一无标点片段里
重复出现的 99 也只剩一个，所以上一份报告所称的"逐次判定"实际并不成立。

### 修复

两条规则，都作用在**每一次出现**上：

1. 断言边界由标点**和连接词**共同决定：`而是|但是|不过|然而|可是|并且|同时|另外|
   此外|那么|但|却|且|则`。有没有逗号不是安全与否的依据。`则`/`那么` 同时结束条件句
   的作用范围。
2. 豁免必须由**这一次出现之前、同一断言之内**的否定词或归属词给出，且被豁免的数值
   必须是提问者自己说出来的。"段里别处有个对的数字"不再是豁免理由。

条件词（`如果`/`若`/`假设`）单独不足以豁免任何数值。因为 `则`/`那么` 是断言分隔符，
条件词能与数值同段，只可能是数值落在条件本身里（`如果按你说的99天计算`）；
`如果入职满一年则每年有99天` 的 99 已被切到下一段，拿不到豁免。

### 修复后（A2 矩阵）

| 答案 | 预期 | 结果 |
|---|---|---|
| 不是99天而是5天 | 可交付 | ✔ |
| 不是5天而是99天 | 拦截 | ✔ |
| 每年99天且可以先休5天 | 拦截 | ✔ |
| 每年99天且没有特殊限制 | 拦截 | ✔ |
| 并不是所有人都有99天但正式员工每年确实有99天 | 拦截 | ✔ |
| 如果入职满一年则每年有99天 | 拦截 | ✔ |
| 如果按你说的99天计算，资料并未这样规定；原文写的是5天 | 可交付 | ✔ |

变体测试（`ModifierScopeTests`）另外证明判定跟着语言走而不是跟着某个关键词：

- **标点不是安全依据**：逗号 / 句号 / `且` / `但` 四种写法的同一对断言，判定一致；
- **连接词可替换**：`且|并且|但|但是|不过|然而|同时|，` 八种，判定一致；
- **数值替换即翻转**：同一句式 `年假不是{a}天而是{b}天`，(99,5) 放行、(5,99) 拦截；
- **否定位置**：`没有99天这一说` 放行；同一断言内**数值在前、否定在后**的
  `正式员工每年享有99天带薪年假没有特殊限制`（无标点、无连接词）拦截——这一条正是
  "看数值之前"与"看整段"的分水岭，撤销验证也用它（第 6 节）；
- **重复数值逐次判定**：前否后肯拦截；每一次都被否定则放行；
- **豁免不外溢**：提问者没说过的 `不是77天` 仍然拦截。

## 4. 工作包 B：统一正文清理（R1 + R2 收尾）

### R1 复现（修复前）

首轮不是 JSON → 纯文本回退；回退这次返回
`<think>检查资料</think>{"answer":"…5天…[来源1]"}`。普通 API 返回值与数据库都是
整个 `{"answer":…}` 字符串。单独 JSON、单独思考标签加纯文本都已通过，**组合后失败**。

根因是只试一次 JSON 解析，失败就去壳直接返回，没有再看刚露出来的合法信封。

### R2 复现（修复前）

answer 字段为 ` \n正式员工每年享有5天带薪年假。[来源1]\n ` 时：

```text
plain  = '正式员工每年享有5天带薪年假。[来源1]'
stream = ' \n正式员工每年享有5天带薪年假。[来源1]\n '
```

两侧各调用一次模型，落库正文相同（API 消费层在拼接后 `.strip()`），但**已经发出去的
delta 与普通返回值不同**。

### 修复

清理顺序集中在 `extract_answer_text()` 一处：**先原样试信封 → 再去壳试信封 →
否则按去壳纯文本**，并在出口归一首尾空白。顺序不能反：answer 字段里合法地写着
`<think>` 字样时，先去壳会把正文本身改坏（有专门测试守住）。

首尾空白同时在 `decide_delivery()` 入口归一——那是**发出任何 delta 之前**两条接口
最后一个共同入口。落库前再 strip 救不了已经发出去的正文。

### 修复后（B 矩阵；每格都检查 API 返回值 / **未经 strip 的原始 delta 拼接** / 落库正文）

| 形态 | 普通接口 | SSE 原始 delta | 落库 | 生成次数 |
|---|---|---|---|---|
| 纯文本（回退） | 正文 | —（见下） | 正文 | 2 |
| 合法信封 | 正文 | 正文 | 正文 | 1 |
| 思考标签 + 纯文本（回退） | 正文 | —（见下） | 正文 | 2 |
| 思考标签 + 信封（回退） | 正文 | —（见下） | 正文 | 2 |
| answer 字段首尾含空格/换行 | 正文 | 正文 | 正文 | 1 |

三种"—"是**有意保留的既有契约**，不是遗漏：流式接口收到裸文本或带外壳的信封属于
结构化格式错误，按原契约抛错、发 `error`、**不落库**，不做静默修复。任务单明确要求
"保留流式传输/结构化格式错误的原有错误和不落库契约"，且不要求容错任意外层格式。
测试 `test_the_stream_keeps_its_format_error_contract` 正面断言了这一点
（终态 `error`、正文不含 `"answer"`、数据库为空）。

保留的既有保护：共享复查与无条件缓冲、首轮可交付只生成 1 次、需要复查时至多 2 次、
**解析回退已用掉第二次时不再生成第三次**（`test_the_fallback_never_leaks_an_envelope_or_a_shell`
断言 `calls == 2`）、传输错误不落库、会话锁、知识版本检查。

## 5. 工作包 C：路由泛化（R3）

### 复现与根因

| 公开诊断例 | 修复前 | 根因 |
|---|---|---|
| `谢啦，祝你接下来一切顺利。` | document_only | `谢啦` 不在社交表（只有 `谢谢`/`多谢`/`感谢`），祝愿语完全不认识 → 没有任何分句带社交标记，`_is_direct` 直接返回 False |
| `给我薪资疑问反馈时限的原始条款，制度概览就免了。` | wiki_document | 否定在标记**之后**：后向窗口看不到它，前向模式要求"否定词 + 供给动词"，而 `免` 不供给任何东西 |

### 修复

- 新增 `SOCIAL_THANKS_MARKERS`（`谢啦`/`谢了`/`太感谢`/`有劳`…）与
  `SOCIAL_WISH_MARKERS`（`祝你`/`一切顺利`/`保重`/`节日快乐`…），并入 `SOCIAL_MARKERS`；
  新增 `SOCIAL_TIME_FILLER`（`接下来`/`往后`/`最近`…）在判断"是否纯寒暄"时一并剥离。
  祝愿语按**整词**收录，裸 `顺利` 不收——否则 `报销流程顺利吗？走到哪一步了` 会被当成
  寒暄（有对照测试）。
- 新增 `_POST_DISMISSAL_PATTERN`，识别标记之后的推却（`就免了`/`免了`/`不用了`/
  `不必了`/`跳过`/`略过`/`就算了`）。`免了` 带负向后顾断言，避免 `避免了`、`以免了`
  被当成推却（有对照测试）。

`_is_direct` 的守卫未变：任何一个分句提出真实请求，整条消息就不是寒暄。

## 9. 残余问题与未完成验证

### 9.1 已知的保守取舍（会误拒，不会编造）

三处都朝"拒答"方向偏，符合任务单"无法建立免责关系时使用原有复查/拒答流程，
不猜测"的要求，但会造成误拒，如实列出：

1. **数值之后的否定不构成豁免**。`每年99天这个说法并不准确。[来源1]` 会被拦截
   （实测 `ungrounded_quantity`），尽管它语义上确实在否定 99。区分"回指该断言的
   否定"与"句子后半段的无关否定"需要更强的结构分析，本轮没有做。
2. **`不但…而且` 会在 `但` 处被切开**。`不但有99天而且还能调休` 拦截。分隔符表为
   了识别 `但`/`但是` 而收下了这个代价。
3. **证据用不支持写法、答案用等价阿拉伯数字时会误拒**。证据 `一万两千件` + 答案
   `12000件` → 拦截；答案同样写 `一万两千件` → 放行。因为不支持的数词只能与
   一模一样的数词相等，不与任何算出来的值相等。

三种情形都由既有的有界复查有机会挽救（一次），且失败结果是统一拒答文案，不是错误事实。
