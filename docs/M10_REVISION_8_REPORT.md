## 4. P1：用原文的边界，不用检查窗口的末尾

### 复现（修复前）

```text
公司规定的99天不对5天内入职的员工公开。[来源1]   validate=(True, ok)  两接口各 1 次调用即交付并落库
公司规定的99天不对 第三方公开。[来源1]           validate=(True, ok)  同上
正式员工每年休99天有误\t工补贴。[来源1]          validate=(True, ok)  同上
```

首轮被判可交付，因此**既有的那次复查根本不会触发**，预设的正确第二次响应用不上。

### 根因

两条路径，同一个毛病：**边界判断没有看真正的原文。**

- 第一例：`following` 停在下一个数量 `5天` 之前，所以交给正则的字符串只有 `不对`，
  `$` 当然成立——可原文后面还有 `5天内入职的员工公开`。下一个数量的作用是限制**背书
  归属**的扫描范围，不该被当成语法上的句末。
- 第二、三例：正则把 `\s` 列为合法终止符，看到空格/制表符就批准，后面的宾语（`第三方
  公开`）或词尾（`工补贴`）根本没被读。

### 修复

把边界判断从正则里搬出来，放到一个在**全文坐标**上工作的函数：

```python
def _refutation_ends_cleanly(text: str, index: int) -> bool:
    while index < len(text) and text[index] in _REFUTATION_PARTICLES:
        index += 1        # 语气词：`不对吧`
    while index < len(text) and text[index].isspace():
        index += 1        # 空白可以有，但它自己不算结束
    return index >= len(text) or text[index] in _CLAUSE_PUNCTUATION
```

调用处把窗口内的匹配位置换算回全文：

```python
trailing = text[end:following]
for match in _REFUTATION_PATTERN.finditer(trailing):
    if _governs(trailing[: match.start()]) and _refutation_ends_cleanly(
        text, end + match.end()
    ):
        return True
```

四种情况现在是分开的：**真实句末**（到全文结尾）、**真实句读**（标点或引用括号）、
**检查窗口末尾**（不再是结束）、**空白**（只能出现在真实句读之前）。

没有把 `$` 换成另一个仍作用于截断串的锚点，也没有对 `5`、`第三方`、`工补贴` 写任何
排除词。

### 修复后

| 答案 | 结束位置之后是什么 | 结果 |
|---|---|---|
| `99天不对5天内入职的员工公开` | `5`（全文里还有内容） | 拦截 ✔ |
| `99天不对第三方公开`（无下一数量） | `第` | 拦截 ✔ |
| `99天不对 第三方公开` | 空格→`第` | 拦截 ✔ |
| `99天有误\t工补贴` | 制表符→`工` | 拦截 ✔ |
| `你说的99天不对，原文写的是5天` | `，` | 交付 ✔ |
| `你说的99天不对 ，原文写的是5天` | 空格→`，` | 交付 ✔ |
| `你说的99天不对`（全文结束） | 全文末尾 | 交付 ✔ |
| `你说的99天不对[来源1]` | `[` | 交付 ✔ |

`不是99天。5天才对。[来源1]` 与逐次数值判定未受影响：下一个数量仍然只限制背书归属
的范围，没有被删掉，也没有被扩大。

## 5. P2：主题必须被正向识别

### 复现（修复前）

六个无引用输出被判为 `(True, refusal)`：

```text
年假带薪至于奖金无法确定。          员工有年假至于奖金无法确定。
奖金无法确定另年假为带薪。          奖金无法确定员工有年假。
不是无法确定年假是带薪的。          年假带薪奖金无法确定。
```

### 根因

`topic`/`about` 是 `[^标点]{0,12}` / `{0,16}`——**任意**短片段，只排除数量和几个连接词。
字数少和"没命中已知坏词"都不能证明它是名词主题。外层虽然把整段字符消费干净了，
内层仍然是"没找到坏东西就批准"。往排除表里加 `至于`、`另`、`带薪`、`不是` 只是继续
枚举，依据本身没变。

第三例还多一层：拒答谓语**本身被否定**（`不是无法确定…`），却仍拿到纯拒答资格。

### 修复

主题改为**由名词表正向拼出**——这是给予豁免的全部依据：

```python
_TOPIC_PHRASE = r"(?:(?:<名词>)(?:的|和|与|及|或|、|等)?)*"
```

`_TOPIC_NOUNS` 是一张有限的名词表（奖金金额、年假天数、补贴标准、报销上限、期限、
流程、制度、正式员工、这个问题、资料、原文…）。`topic` 与 `about` 都必须完全由它们
（可用连接词粘合）拼成；**拼不出来就不是主题，这一段匹配失败，整段随之失去资格。**

同时加了谓语极性检查 `(?<![不未非无是])`：拒答谓语前面紧挨着否定词时，这不是拒答。

`_TOPIC_BREAKERS` 与 `_carries_assertion()` **已删除**——正向语法把它们全部覆盖了
（名词表里没有数字，也没有连接词），继续留着就是两套依据并存。

**任意剩余文本如何失败**：`年假带薪` 里 `年假` 是名词、`带薪` 不是 → 拼不完 →
主题不成立 → 该子句不匹配 → 外层在这个位置拿不到子句 → 整段不是纯拒答。
`员工有年假` 里 `员工` 是名词、`有` 不是 → 同理。`至于奖金`、`另年假为带薪`、
`不是` 都在第一个字就失败。

### 修复后

| 文本 | 结果 |
|---|---|
| 六个反例（事实在前/在后/无连接词/否定谓语） | `(False, no_citation)`，两接口交付统一拒答 ✔ |
| 以上任一**加 `[来源1]`** | 交付 ✔ |
| `无法确定奖金金额。` / `奖金金额无法确定。` / `年假天数无法确定。` | 免引用交付 ✔ |
| `暂时无法确定奖金金额。` / `根据资料无法回答这个问题。` | 免引用交付 ✔ |
| `原文中未提及奖金金额。` / `资料不足，无法确定。` / `资料中没有相关记录，无法确定。` | 免引用交付 ✔ |
| `根据现有资料无法确定奖金金额，也无法确定补贴标准。`（逗号/分号两种） | 免引用交付 ✔ |
| `无法确定报销上限和审批流程。` | 免引用交付 ✔ |
| 第六/七轮的混合拒答反例 | 仍需引用 ✔ |
| `……无法确定奖金金额。……每年享有99天带薪年假。[来源1]` | `(False, ungrounded_quantity)`，第四轮修复未受影响 ✔ |

## 10. 残余问题与未完成验证

### 10.1 正向识别批准什么，剩下的怎么失败

两处豁免现在都是**有限的正向表**，认不出来就不豁免：

- **驳斥**：只认 `不对`、`有误`、`并不正确`、`并不准确`、`不属实`、`并非如此`、
  `是错的`、`站不住脚`、`不足为据` 这几类，且必须以真实句读或全文末尾收尾。
  模型若写 `99天这个数字与原文对不上`，表外，不豁免。
- **拒答主题**：只认 `_TOPIC_NOUNS` 里的名词（可用 `的/和/与/及/或/、/等` 粘合）。
  `无法确定各地区差旅补助口径` 里的 `各地区差旅补助` 不在表内 → 不算纯拒答 → 要引用。

两者都落到"需要引用/走既有复查"一侧。**这是保守方向，也是真实的误拒代价**，
不是零成本。
